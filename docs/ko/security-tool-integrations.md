# 보안 보고서 연동

ScopeWeaver는 YeepForge, AdStrike, confirmesc가 내보낸 JSON 보고서를 읽고, 두 제공자 항목을 읽기 전용 카탈로그에 나열할 수 있습니다. 모두 선택 기능이며 기본값은 꺼짐입니다.

포함되는 것:

- 설정 > MCP의 제공자 항목 두 개(종류 `yeepforge`, `adstrike`). 카탈로그 전용입니다.
- 보고서를 읽는 스킬 세 개: `yeepforge`, `adstrike`, `confirmesc`.
- 작업의 보고서 탭에서 보고서 가져오기.

English: [Security report integration](../security-tool-integrations.md)

## 설정

ScopeWeaver는 이 도구들을 설치하지 않습니다. 운영자가 따로 설치합니다.

1. 설정 > MCP를 엽니다. `YeepForge`와 `AdStrike` 항목은 stdio 전송, 비활성 상태로 추가되어 있습니다. 이름이 비어 있을 때만 추가되며, 같은 이름의 기존 서버는 그대로 둡니다.
2. 명령(인터프리터)과 인자(진입점)를 입력합니다. 절대 경로를 사용하세요. 서버는 명령을 일반 실행 파일 조회로 찾으므로, 이름만 쓰면 `PATH`에 따라 달라집니다.
3. 이 항목은 stdio만 허용합니다. URL이나 TLS 검증 해제는 거부됩니다.
4. 종류는 항목을 만든 뒤 바꿀 수 없습니다.
5. 선택 항목인 소스 리비전은 설치한 업스트림 커밋의 40자 소문자 SHA-1입니다. 기대값을 기록할 뿐 실제 실행 코드를 증명하지 않습니다. 출처 확인(provenance)은 항상 검증되지 않음으로 표시됩니다.

## 카탈로그 동작

- 제공자를 저장해도 시작되지 않습니다.
- 활성은 명시적인 새로 고침 대상이 될 수 있다는 뜻입니다. 에이전트가 호출할 수 있다는 뜻이 아닙니다.
- 새로 고침은 제공자를 한 번 시작해 도구 목록을 가져오고 닫습니다. 도구 호출은 보내지 않으며, 제공자의 stderr는 버립니다.
- 에이전트는 제공자의 도구를 받지 않습니다. 에이전트에 보이는 것은 캐시된 상태를 알려 주는 읽기 전용 `security_catalog` 도우미뿐이며, `callable` 값은 항상 false입니다.

상태 값:

| 상태 | 의미 |
| --- | --- |
| `not_configured` | 명령이 설정되지 않음. |
| `disabled` | 항목이 꺼져 있음. |
| `not_discovered` | 새로 고침한 적 없음. |
| `discovered` | 캐시가 현재 설정과 일치하고 마지막 새로 고침이 성공함. |
| `stale` | 마지막 새로 고침 이후 설정이 바뀜. 다시 새로 고침하세요. |
| `unavailable` | 마지막 새로 고침이 실패함. 이전 도구 이름은 유지하지 않고 지웁니다. |

출처 확인은 별도 필드이며 항상 `unverified`입니다. ScopeWeaver는 설치된 실행 파일이 무엇인지 인증하지 않습니다.

화면에는 예상 리비전, 제공자가 스스로 보고한 버전(인증되지 않음), 측정할 수 있었던 경우 진입점 파일의 SHA-256도 표시됩니다.

보고서 가져오기는 이 항목들이 필요 없습니다. 제공자를 설치하지 않아도 동작합니다.

## 보고서 가져오기

1. 설정 > MCP에서 보고서 가져오기 스위치를 켭니다. `security_reports_enabled` 설정으로 저장되며 기본값은 꺼짐입니다.
2. 작업의 보고서 탭에서 해당 제작 도구의 JSON 내보내기 파일을 업로드합니다.

제한: 1 MiB, 결과 1000개, 중첩 깊이 32. 요청은 `application/json`이어야 합니다. 지원 프로필:

| 제작 도구 | 프로필 |
| --- | --- |
| `yeepforge` | `yeepforge-json-ee07fe3` |
| `adstrike` | `adstrike-json-2.0` |
| `confirmesc` | `confirmesc-json-36f1ec8` |

보고서 전체를 메모리에서 검증한 뒤에만 무언가를 보관합니다. 검증에 실패하면 아무것도 저장하지 않습니다.

보관: 결과의 위치, 정규화한 심각도와 신뢰도(알 수 없는 값은 `unknown`), 제작 도구가 보고한 CVSS 수치, 유효한 CWE·CVE·OWASP·ATT&CK 식별자, 유효한 경우 제작 도구의 타임스탬프, 제작 도구와 프로필 이름, 원본과 정제본의 해시, 가져온 시각, 개수, 완전성 플래그(`unknown`, `no_observations`, `has_errors`).

버림: 모든 자유 서술(제목, 설명, 증거, 조치 방법, 명령), 호스트, 사용자, URL, 자격 증명, 알 수 없는 필드. 화면에 보이는 제목과 안내는 보관한 분류로 생성한 것입니다. 원본 파일은 저장하지 않습니다.

가져온 항목은 상태가 `producer_reported`인 관찰 사실 하나입니다. 확인된 취약점이 아니며 취약점 항목도 만들지 않습니다. 심각도와 신뢰도는 제작 도구가 주장한 값입니다. `no_observations`나 `has_errors`가 대상이 깨끗하다는 뜻은 아닙니다.

같은 작업에 같은 파일을 다시 올리면 새 항목 대신 저장된 항목을 돌려줍니다(HTTP 200, `duplicate: true`). 기능을 끄면 기존 가져오기 기록은 계속 읽을 수 있고 새 가져오기는 거부됩니다.

## 에이전트

스킬 세 개는 선택 사항입니다. 기존 스킬 표시 설정으로 에이전트에게 보이게 하세요. `security_catalog` 도우미는 보고서 가져오기가 켜져 있고, 도우미가 호출한 에이전트에 바인딩되어 있으며, 그 에이전트가 활성일 때만 응답합니다. 하위 작업에서 가져온 항목을 다시 쓰려면 그 항목을 소스로 명시해야 합니다. 상위 작업 링크만으로는 이어지지 않습니다.

## 기존 바이너리 설치 업그레이드

자체 업데이트는 바이너리만 교체하고 스킬 파일은 건드리지 않습니다. `cp -r <풀어낸_디렉터리>/skills ./`를 쓰면 직접 수정한 스킬을 덮어씁니다. 대신 인증된 업로드 API로, `overwrite=true` 없이 없는 스킬만 설치하세요.

- 스킬 `.zip`을 멀티파트 `file` 필드에 담아 `POST /api/skills/upload`로 보냅니다.
- 스킬 이름은 SKILL.md의 `name:` 필드에서 가져옵니다.
- 같은 이름의 스킬이 이미 있으면 409를 반환하고 기존 스킬은 그대로 유지됩니다. 새 스킬은 201을 반환합니다.
- `overwrite=true`일 때만 기존 스킬을 교체하므로 붙이지 마세요.

릴리스 아카이브에는 `skills/yeepforge`, `skills/adstrike`, `skills/confirmesc`가 들어 있습니다. 각 디렉터리를 zip으로 묶어 업로드하세요.

## 롤백

다음 순서로 진행합니다.

1. 보고서 가져오기 스위치를 끕니다.
2. 제공자 항목 두 개를 비활성화합니다.
3. 에이전트 바인딩을 제거합니다.
4. 실행 중인 탐색 프로세스가 없는지 확인합니다.
5. 이전 바이너리(v0.3.1, 커밋 `d999b19`)를 시작합니다.

추가된 스키마와 정제된 사실 데이터는 남습니다. 연동이 바꾼 값(예: 스킬 표시 설정)만 되돌리세요.
